# 桌面宠物的记忆

最后更新：2026-08-03

## 项目定位

- 产品名：源源上班搭子。
- 这是给一位女孩子做的 Windows 桌面宠物，核心是陪伴感和“活着”的感觉，不做臃肿游戏。
- 猫咪形象必须严格参考用户提供的橘白猫照片；比例可以略萌化，但不能夸张，也不能私自改变形象。
- 首次启动让使用者自行输入猫咪名字。
- 独立安装运行，不依赖 Python 或其他外部环境；目标是轻量、低占用。

## 当前技术与版本

- Godot 4.7.1，Windows 单文件 EXE，透明悬浮窗口。
- 正式保留版本：v1.3.2，不覆盖。
- 当前测试版本：v1.3.3（待机小动作测试）。
- 动画以绿幕视频抠像播放，已做首尾帧亮度、色度和对比度匹配；现阶段效果用户已暂时认可。
- 所有动画切换应保持同一机位、比例、位置和色调，不能闪帧、重影或突然变亮/变暗。

## 已确认的宠物体验

- 大部分时间安静坐着，不要持续播放大动作，也不要像完全静止的贴纸。
- 静止约 5～10 秒后，随机出现低存在感动作；待机动作随机播放，不指定首次优先动作。
- 已有/使用中的动作包括：待机 1、待机 2、待机 3、待机小动作（耳朵/尾巴）、打哈欠一次、舔手整理毛发、生气挠屏幕、翻滚躺下卖萌及按住/松开衔接。
- 不再制作“头部 360°追踪鼠标”；不做喂食状态和压力值。
- 左键用于拖动或互动，不用于输入聊天；右键弹出精简菜单。
- UI 使用活力黄黑风格，尺寸偏小；说话气泡采用马赛克/像素风，贴近猫但箭头不能戳到耳朵。
- 程序启动后不显示在任务栏，常驻系统托盘。
- 天气通过猫咪闲暇动作表达，例如雨天头顶乌云下雨、晴天偶尔搬沙滩椅晒太阳。

## 文案与互动规则

- 文案要口语化、简短，可以温柔、毒舌或吐槽，不要官方腔。
- 高频软件重点覆盖微信、办公软件、浏览器、钉钉；打开软件时触发对应吐槽。
- 微信可用语气示例：谁又给你发消息？／这个软件有什么魔力，每次打开它一会开心一会烦恼？／一看就不是什么正经软件，我打赌上班肯定用不到。／随便发个表情应付一下就行。
- 点击多次后的反馈要有多条随机文案，不能总说“那我让你摸一下好了”。
- 主动说话和表情应偶尔触发，避免反复弹同一句。
- 12:00 提醒吃饭；17:55 提醒下班打卡。
- 18:00 后仍在线时偶尔说加班吐槽，但主人很少加班，因此不要高频或一直说。

## 心形礼物惊喜（当前暂停点）

- 参考已有 `heart_show.py` 的效果，已开始原生移植到 Godot；成品不能依赖 Python，也不能调用外部 EXE。
- 运行 2～4 小时后随机询问：“我有一份礼物想送给你，你要吗？”
- 用户接受则播放心形代码礼物；拒绝则温柔回应下次再送。
- 完整触发后冷却 48 小时；右键菜单中不提供手动入口，保持惊喜感。
- 本地已实现礼物调度、原生心形窗口、接受/拒绝按钮和基础测试；调度范围、48 小时冷却、无右键入口、微信文案测试已经通过。
- 尚未完成：修复原生心形窗口的桌面可见性后重新截图验收、全量回归、导出新测试 EXE。因此不能声称该功能已交付。

## 下次继续的顺序

2. 分别截图验收礼物询问框与心形动画，确认窗口层级、位置、帧率和关闭逻辑。
3. 全量回归桌宠已有动作、右键菜单、软件吐槽、提醒和托盘行为。
4. 仅导出新的测试版本；得到用户认可前绝不覆盖 v1.3.2。

## 协作和验收偏好

- 后续桌宠验收严格遵循 `hatch-pet` 技能要求。
- 小改动要快速落地并及时反馈，避免用户长时间空等。
- 在说“做好了”之前必须自行启动、截图并检查实际效果；不能只看代码或测试通过。
- 保留可修改接口，所有版本改动可回退，稳定版本不得擅自覆盖。
