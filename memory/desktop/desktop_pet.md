最后更新：2026-08-03

## 项目定位

- 产品名：源源上班搭子。
- 给一位女孩子制作的 Windows 桌面宠物，核心是轻量、陪伴感和“活着”的感觉，不做臃肿养成游戏。
- 猫咪形象必须严格参考用户提供的橘白猫照片；比例可轻微萌化，但不能夸张或私自改造。
- 第一次启动由使用者输入猫咪名字。
- 独立安装运行，不要求对方安装 Python 或其他环境；稳定、低占用优先。

## 心形礼物：正确实现与关键教训

用户真正要的效果：无论当前正在使用微信、浏览器还是其他软件，心形小卡片直接置顶浮在当前界面上；不切换界面、不黑屏、不换壁纸、不显示 Godot 自己的窗口。

原始 `heart_show.py` 的正确结构：

- 根 Tk 窗口立即 `withdraw()` 隐藏。
- 约 200 个无边框、置顶的 `Toplevel` 小卡片窗口独立出现。
- 根本不存在全屏背景窗口，所以不会黑屏，当前软件仍在下面正常显示。

v1.3.12 已停止 Godot 全屏礼物方案，改为：

- 把已经验证正常的 `心形弹窗动画.exe` 作为 `assets/bin/heart_popup.exe` 内置进桌宠 EXE。
- `export_presets.cfg` 使用 `include_filter="assets/bin/*.exe"` 打包资源。
- 首次触发时，`main.gd::_prepare_heart_gift_executable()` 将其释放到 `user://runtime/heart_popup_v1.exe`。
- `main.gd::_play_heart_gift(false)` 直接启动该程序，并等待它正常结束。
- 接收礼物后的触发冷却仍为 48 小时；右键菜单没有礼物入口，保持惊喜感。
- 测试构建包含 `gift_test_build`，启动后自动播放礼物，便于人工验收。

不要再采用以下已失败路线：

- 复用桌宠主窗口做全屏礼物：结束后闪屏、无法操作、疑似重开宠物。
- Godot 子窗口/全屏 Canvas：出现 300×400 范围限制、黑屏、小方块或额外 Godot 界面。
- 截屏作为背景：会把当时打开的软件界面冻结进礼物画面。
- 黑色背景或壁纸背景：都不是用户要求。
- Godot 透明全屏根窗口：本机实际仍出现黑屏，不能继续沿用。

已停用的失败包均以 `.bak` 保留，尤其 v1.3.4 至 v1.3.11；不要重新启用。

## 其他已确认产品要求

- 大部分时间安静坐着；静止约 5～10 秒后随机出现低存在感动作，待机动作随机且不指定首次优先。
- 动作包括待机 1/2/3、待机小动作、单次打哈欠、舔手整理毛发、生气挠屏幕、翻滚躺下卖萌及按住/松开衔接。
- 不再制作 360°追踪鼠标转头；不做喂食与压力状态。
- 左键用于拖动或互动，右键为精简菜单；启动后不显示任务栏按钮，进入托盘。
- UI 为活力黄黑风格；马赛克像素气泡靠近猫咪，但箭头不能戳耳朵。
- 文案要口语化、简短，可温柔、毒舌或吐槽，避免官方腔和重复。
- 高频软件重点：微信、办公软件、浏览器、钉钉。
- 12:00 提醒吃饭；17:55 提醒下班打卡；18:00 后在线可偶尔吐槽加班，但主人很少加班，不要高频。
- 天气通过闲暇动作表现，例如雨天头顶乌云、晴天搬出沙滩椅晒太阳。
